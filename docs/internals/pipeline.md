# Translation pipeline internals

Read before changing `packages/core/src/pipeline.ts`, `terms.ts`, `agreement.ts`, `punctuation.ts`, the tag helpers in `packages/shared/src/utils/text.ts`, or the prompt builders in `packages/adapters/src/base.ts`. The numbers quoted are bench results (`scripts/bench/`) that justify each rule; re-measure before changing one.

## Flow

**Pipeline flow**: Preprocess (tag inject) → Context retrieval → Translate → Validate (glossary check) → Postprocess (tag strip) → Agreement repair (gated, see below).

## Term Set

**Term Set** (`TermSet`, `packages/core/src/terms.ts`): `runPipeline` matches the hits, then builds one `TermSet(text, realHits, extraGlossaryHits, targetLang, imageMode)` that owns the tagged and code-switched sources and `read(raw, kept?)`, the single postprocess chain every attempt, the kept-word re-read and the repair output go through: tag strip → `normalizeWhitespace` → `fixTermAgreement` → `dropAddedFullStop` → coverage on `splitArabicArticles`' text; `read()` also returns `forced`. It also gives `reminder()`, `tagCheckCandidates()`/`keptWords()`, `driftCandidates()`/`drifted()` and `repairTerms()`. It takes hits, never the store, so test it on plain strings (`terms.test.ts`); don't call the chain's helpers from the pipeline directly. Its helpers stay in `shared/utils/text.ts` on purpose (the mock adapter needs the tag strip; see `docs/adr/0001-term-helpers-stay-in-shared.md`). `runPipeline` keeps retries, best-attempt choice, streaming, cancellation, the tag-check and repair calls, the drift check's and the repair's acceptance gates.

## Glossary retries

A real glossary term missing from the output triggers a `glossaryReminder` retry: strict mode retries up to `maxRetries` and then throws `GLOSSARY_STRICT_MISS`; prefer mode (the default) retries exactly twice (fixed, `maxRetries` doesn't apply) and returns whichever attempt has the highest coverage (ties keep the earliest; `metadata.retries` counts the retries either way), never throwing for a miss. In both modes the **last** retry is code-switched (`injectGlossaryTags(text, hits, realHits)`): each real hit is sent with its target term in place of the source word, sentinel / `extraGlossaryHits` tags unchanged, and no `glossaryReminder`. When the source word and the term share no writing system and the term is neither Latin-script nor Han/kana/Hangul (`keepsSourceWord()` in `text.ts`), the tag keeps the word as an attribute, `<term translation="الكاش" source="cache">الكاش</term>`; otherwise it is `<term translation="hôte">hôte</term>`. Without the attribute a term that is also another word drifts the meaning (#116: P4 `Cleared the {name} cache.` with `cache → الكاش`, which also reads as "cash", became a payment sentence in 20/20 forced code-switched attempts). Don't add it for same-script pairs: the model then copies the source word (A11 it `server → host` code-switched term 9/20 → 4/20). Nor for CJK terms: it bought no coverage on zh/ja/ko (no English leaked either) but dropped placeholders (ja `Cleared the {name} cache.` → `キャッシュ`: sentinel kept 42/60 → 29/60). Nor for Latin-script terms: from a non-Latin source the model translates the source word itself (ja→en `サーバー → host`: the last retry wrote "server" in 6/16 attempts with the attribute, 0/18 without). The source word in the text (`cache (الكاش)`) or in a prompt line also fixed P4 but made G9 drop `كوميت` (the model translates the English word itself); earlier retries send the tagged source plus the reminder (strict with `maxRetries: 1` code-switches its only retry). `extraGlossaryHits` never trigger either retry.

## Tag strip

**Tag strip** (`stripGlossaryTags`, `packages/shared/src/utils/text.ts`): a complete `<term translation="X">inner</term>` becomes X unless `keptTermForm(inner, X)` keeps the model's own form (#116): inner (trimmed, one pair of surrounding quotes dropped) contains X case-insensitively, has no more whitespace-separated words than X and no `<`/`>`; the matched span is rewritten as X exactly, or as `capitalizeTerm(X)` when the model wrote that (de `Bereitstellen` for `bereitstellen`, fr `Hôtes`), so coverage still finds it (ar `الكوميت`/`انشر` for `كوميت`/`نشر`). When an all-caps match is rewritten, the letters glued after it are lowercased with it (`HÔTES` → `hôtes`, not `hôteS`; Greek final sigma holds), text before it or after a non-letter stays (`L'HÔTE` → `L'hôte`, `__TLPH_0__HÔTES` keeps its sentinel), and a match starting the word at a sentence start gets `capitalizeTerm(X)` (`HÔTES sont` → `Hôtes sont`). A replaced inner whose first letter is uppercase at the start of the text, a line or a sentence (after `.!?…` + whitespace) gets `capitalizeTerm(X)` (fr `<term translation="hôte">Serveur</term> : détails` → `Hôte : détails`; tracked per segment in `removeTermTags`, still linear). `capitalizeTerm()` only raises the first letter of a term with no uppercase letter (`iOS`, `Zweig` unchanged); coverage accepts X or `capitalizeTerm(X)` (nothing else case-insensitive), and `fixTermAgreement()` runs its fix-ups on both forms. File-mode bench (`lcStart` column: glossary leaves whose source starts uppercase but whose value starts lowercase): fr 21/240 → 1/240, de 12/99 → 0/99; agreement and strict-glossary benches unchanged. Unclosed tags and sentinel attributes always become X. Keep the strip linear-time (`removeTermTags`, no regex rescans).

## Agreement fix-ups

In that chain, after the tag strip, `fixTermAgreement()` (`packages/core/src/agreement.ts`) drops quotes / em dashes wrapped around a real target term, and for fr/it drops a lone em dash before it and applies elision before a vowel- or mute-h-initial term (`le hôte` → `l'hôte`; French aspirated-h and all y-initial words excluded), drops a detached Arabic `الـ` before an `ال`-initial term, merges a detached or doubled `ل` into one (`لـ الكاش` / `للالكاش` → `للكاش`; `للغة` when the stem starts with `ل`, `mergeArabicLam()`), and attaches a detached `الـ` (after an optional proclitic) to any other Arabic-script term (`بالـ نشر` → `بالنشر`; Latin-script terms keep `الـ API`); it never touches sentinels. For Arabic targets, coverage (every attempt and the repair check) counts that `ل` merge as the term (`splitArabicArticles()` in `agreement.ts`; harakat are dropped first, as coverage drops combining marks anyway, so `للّغة` counts; not after `ل`/`ا`, so the misspelt `لللغة` stays a miss): exact coverage scored a correct `للغة` as a miss, so prefer mode retried and returned a broken `للاللغة` instead (agreement bench A12–A15: agree 16/40 → 37/40, mean calls 2.83 → 2.25).

## Added full stop

Next in the chain, `dropAddedFullStop()` (`punctuation.ts`, not in image mode) drops one trailing full stop (`.。．۔।`, trailing LRM/RLM/ALM skipped and kept) when the source has no sentence-final punctuation (`endsWithPunctuation()`, shared with `appendsEndPunctuation()`; it looks past trailing whitespace, closing quotes/brackets, markdown closers `*` `_` `` ` ``, bidi marks and placeholder sentinels, so `Read the __TLPH_0__docs.__TLPH_1__` and `**Saved.**` count as punctuated): `Save changes` → `Enregistrer les modifications.` (the model did that to ~6 of 131 catalog labels per language per run). A `.` is kept when the last word has any other dot (`..`, `z.B.`), is one letter (`z. B.`) or an `ABBREVIATIONS` entry (`etc.`, also after a hyphen: `Bestell-Nr.`), or when a glossary target term or one-piece form ends with it. Offline replay of every saved file-mode run: 326 leaves changed (fr 64, de 132, ar 130), all period-only.

## Tag check

**Tag check** (`finish()` in `pipeline.ts`, before the agreement repair): when the attempt about to be returned (prefer mode's best one included; never the code-switched attempt, which already had this source) has a complete tag for a real term T around a word X that `keptTermForm()` rejects while T or a form is already outside every tag as a whole word (`tagCheckCandidates()` in `text.ts`; de `<term translation="bereitstellen">Automatisch</term> nach jedem Commit bereitstellen.`), the pipeline makes one extra call with the code-switched source (no reminder, onChunk or context; signal forwarded) whose output is never returned. When prefer mode's code-switched retry already ran (the best attempt is an earlier one), its output is reused as the answer instead (that retry also had context; no extra call). X is kept (`stripGlossaryTags(raw, forms, kept)`) only if that output, tag-stripped with marks dropped, has T (or a form) as a whole word and, outside T's and its one-piece forms' own occurrences (`Request` in `Pull Request` doesn't count), X as a whole word, case-insensitively (`checkKeepsWord()`; an X that is a part of a split form, `Stellen` of `stellen … bereit`, is never kept); otherwise the strip replaces X as before. Each candidate term is decided on its own from the one answer. Only for a T with exactly one real hit and one tag in the output (with two source occurrences, the outside T may translate the other one); never for sentinels, an X equal to the hit's source word, an X without letters, or when X, T or a form has CJK/kana/Thai/Lao/Khmer/Myanmar letters (no word edges: `キー` in `キーボード`). T stays covered by its outside occurrence, so prefer mode's choice is unaffected; coverage is recomputed after a keep anyway. A failed check strips as before; `CANCELLED` / an aborted signal throws, and no check starts once aborted. `metadata.tagChecked` = an extra check call was made (also when it failed; not set when the retry's output was reused), `metadata.keptWord` = a word was kept. In file mode it runs per `runPipeline` call, so a placeholder retry of the leaf can check again (like the repair). Replay of all saved file-mode runs: it fires on 15 of 9,039 leaves (14 `deploy.auto`, 1 fr `repository.mirror`, where the tag is right: `répertoire` is the model's word for "repository" and must be replaced), with strip answers every leaf is identical to main; measure keep rates with `scripts/bench/tag-check-probe.ts`.

## Drift check

**Drift check** (`finish()` in `pipeline.ts`, with the tag check): the same candidates' limits (`replacedTags()` in `text.ts`: one real hit and one tag for T, no sentinel, X not the source word, has letters, no no-space script, `keptTermForm()` rejects X) but T and its forms appear nowhere outside the tags, and X has more words than the hit's source term (`driftCandidates()`): the tag drifted onto the words around the term (fr `Cache hit rate` → `<term translation="antémémoire">Taux de réussite</term>`, which the strip turned into `Antémémoire`). It shares the tag check's call (or the reused code-switched retry's output; `metadata.tagChecked` as there). When that output, tag-stripped, still has X, or one of X's words of four or more letters not inside T, as a whole word outside T and its one-piece forms, case-insensitively with only Arabic harakat dropped (`checkWritesDriftedWord()`; folding Latin accents matched `archive` to `archivé`), X translated other source words: the answer is `terms.read(check)` instead of the draft, if its missing terms are a subset of the draft's and its sentinel multiset is identical (no length guard: the draft lost words, so the answer is longer by design). That answer is code-switched, so it always goes to the agreement repair; `metadata.tagDrift: true`. Otherwise the tag check's keep decision and the strip run as before. A one-word X for a one-word term is not a candidate: in the saved runs 1,810 of 2,082 replaced tags with no outside term were the model's own word for the term (`serveur`, `répertoire`, `Abteilung`, `رمز`), which the strip rightly replaces; neighbour drift was 171 tags, mostly multi-word. Offline estimate (labelled replay of 10,218 file-mode leaves plus 5 code-switched answers per affected source): about 64 of 147 bad leaves fixed, about 2 synonym leaves changed, 3.6 extra calls per 131-leaf file; ungated it would fix about 77 for 17 calls per file. Single drifted words (fr `commit.message` `<term …>Message</term> de commit`) stay unfixed, and so does that key under any check: its code-switched answers are `validation de validation`.

## Agreement repair

**Agreement repair** (#115, `repairAgreement()` in `pipeline.ts`): gender/case agreement needs the model, so when the *returned* result holds a forced real term, the pipeline makes one extra call with `TranslationRequest.repairTerms` (the real target terms the draft contains; `source` = the draft; no `onChunk`, hits, reminder or context; `signal` forwarded). Forced = the attempt was the code-switched one, or its raw output echoed a real-term tag around a different word (`substitutesTerm()`; a complete tag whose inner `keptTermForm()` keeps, or the tag check keeps, is not a substitution; Mock writes the target inside the tag, so it never fires there). Not for sentinel tags, image mode, or results without real hits; in prefer mode only the winning attempt's flag counts. The repair goes through `fixTermAgreement()` too and is kept only if it changed the text, every term the draft had is still covered, the sentinel multiset is identical, it adds no `*` (the model sometimes bolds the term: `**الكاش**`), it is not just the draft plus sentence-final punctuation the source lacks (`appendsEndPunctuation()`: 13 of 56 applied repairs in the file-mode bench only added a period to a UI label), and the length ratio is within `REPAIR_MAX_LENGTH_RATIO` (1.3) either way; then `metadata.repaired: true`. Otherwise, or on any adapter error, the draft is returned — except cancellation: a `CANCELLED` error or an aborted signal throws `CANCELLED`, and no repair starts once aborted. It runs per leaf in file mode too (same `runPipeline`). TranslateGemma echoes term tags on most glossary hits, so expect the repair on most glossary-bearing translations, not a rare path. Measure agreement changes with `scripts/bench/agreement.ts` (it reports `repairs` / `applied`).

## Prompt builders

**Prompt builders** (`packages/adapters/src/base.ts`): `buildStructuredPrompt(request)` produces the TranslateGemma XML-style prompt and returns `{ prompt, system? }`. `buildNaturalPrompt(request)` produces a generic instruction-style prompt string for non-TranslateGemma models. Everything after the translate line is translated, so instructions never go into `source`: glossary retries (both modes, except the code-switched last one) pass the missing terms as `glossaryReminder` (source → target pairs) and the builders render them before the text. A `sourceLang` of `auto` is never named in the prompt — the builders switch to source-agnostic phrasing. Both builders add a placeholder rule when the source holds `__TLPH_N__` sentinels, sharing one `sentinelTokens()` helper (total occurrences, distinct tokens; tag attributes not double-counted) and asking for each token as many times as in the source. The structured rule's examples are built from the source's own first two distinct tokens (`placeholderExamples()`), so the prompt never names a token the source lacks; fixed example tokens (`…A__`/`…B__`) dropped en→fr placeholder survival from 10/10 to ~4/10 in the bench. Build all token text from the shared prefix/suffix constants, never literals. A `repairTerms` request is not a translation: both builders return `buildRepairPrompt()`, a target-language proofreading prompt (the draft after the template's two blank lines, a short placeholder-copy rule when it has sentinels). It deliberately omits the original source text (the model then re-translated and dropped terms) and term tags (reusing the translate template made it echo tags and mangle the text).

## Streaming

**Streaming**: `PipelineOptions` accepts `onChunk?: (chunk: string) => void`. When present, the pipeline forwards it on the first attempt only (retries are silent to avoid concatenating tokens across attempts). The final text can therefore differ from what was streamed (postprocessing, or a retry's result): the CLI reprints it when it differs and the TUI replaces the pane with `result.translated`. The adapter sets `stream: true` and calls `onChunk` per token via NDJSON, while still accumulating the full response for postprocessing. Adapters that don't support streaming ignore the field. CLI streams tokens to stdout only when it is a TTY — piped stdout receives exactly the final postprocessed translation once; TUI updates the output pane with a 16ms render throttle.

## Image mode

**Image mode**: Pass `imageBase64` in `PipelineOptions` to trigger image translation. In this mode: glossary tag injection is skipped, `source` is set to `""`, and `imageBase64` is forwarded to the adapter unchanged. Context retrieval is also skipped when `queryText` is empty (image-only invocation).
