# File mode internals

Read before changing `packages/core/src/files/`. User-facing behaviour is in `docs/file-translate-guide.md`.

## Overview

**File mode** (`tl translate --file <path>`): translate a JSON or YAML catalog. Orchestrator at `packages/core/src/files/index.ts` walks every string leaf, masks placeholders with ASCII sentinels (`__TLPH_N__` — prefix/suffix are shared constants; core exposes `sentinelFor()`, and the adapter prompt builder derives its enforcement regexes from the same constants), runs the per-leaf pipeline, validates placeholders survived (multiset equality; sentinels reach `runPipeline` as `extraGlossaryHits` (deliberately, see `docs/adr/0002-sentinels-ride-the-glossary-tag-channel.md`), which are tagged but never count toward glossary retries (either mode), reminders or coverage, so a dropped sentinel is retried by `translateLeaf`'s placeholder loop in both glossary modes), then atomic-writes (tmp+rename) to the output path.

## Leaves

`files/leaf.ts` decides what happens to one leaf. `planLeaf()` makes no model call: it returns `keep` (FormatJS metadata, skip heuristics), `refuse` (ICU plural/select in an i18next catalog, ICU that doesn't parse) or `translate` (`icu` or plain), so a dry run and a real run classify every leaf the same way. `translateLeaf()` translates a planned leaf through one `TranslateText` function (the file's `FileTranslator` gives one per leaf, running `runPipeline` with that leaf's context snippets) and returns a **leaf outcome**: `translated` (value, `unhinted`) or `failed` (a `LeafFailure`: message, the tag `--strict` would throw, its hint, and the pipeline error to rethrow). A cancelled call is thrown instead. `strictError()` builds the `--strict` error; `translateFile` decides whether to throw it. Each leaf goes to the pipeline as one or more **translation units** (the whole leaf, or one ICU message or branch), each retried on placeholder mismatch up to 10 times. Test leaf behaviour in `leaf.test.ts` with a scripted `TranslateText`; no stores or adapter needed.

## Catalog formats

JSON and YAML sit behind one seam, `CatalogFormat` in `files/catalog.ts` (`jsonFormat` in `json.ts`, `yamlFormat` in `yaml.ts`). Formats take and return text: `translateFile` alone reads files and does the atomic, validate-before-rename write. `format.open(text)` gives the **source catalog** (`data`, `duplicateKeys`); `retarget({ localeRoot, plurals, existing })` gives the **target catalog** for one target locale, once per source catalog: `source` (the diff source: re-rooted, plurals regenerated), `plurals`, `output` (the existing target or an empty copy of the source's shape; the sync setters and `pruneTarget` change it in place), `revertLeaf(path)` and `serialize()`. The data side lives in `catalog.ts`; a format adds only its own write-back through `FormatHooks`. YAML output is `output` written onto the *source document* by `applyValue()`: the written data is exactly `output`, as in JSON (the target's values win, null and other non-string values included, and keys or items the data lacks are dropped, #160), while comments, scalar styles and key order come from the document wherever the shapes agree; data-only keys are appended at the end of their map, and an equal non-string value keeps its written form (`0x10`, `~`). So `yamlFormat` only renames the document's root key and regenerates its plural groups in `retarget`, which runs before any leaf is set or reverted. The catalog suite checks that the YAML output parses to the same data as the JSON output. Test formats through the interface (`files/__tests__/catalog.test.ts` runs the same scenarios on both, byte for byte).

## Refused formats

**Refuse-by-default** for ARB / xcstrings / Lingui-full — escape hatch is `--format raw-json` with a documented "may corrupt metadata" warning.

## ICU MessageFormat

**ICU MessageFormat** (`files/icu.ts`): values with plural/select/selectordinal/number/date/time, and every FormatJS `defaultMessage` (other FormatJS fields are copied as `metadata`), are parsed with `@formatjs/icu-messageformat-parser` (`ignoreTag: true`, so tags stay literal text for the regular masker) and rebuilt by our own printer — not formatjs's `printAST`, which re-sorts keys and quotes `<tag>` text. Each top-level message and plural/select branch is one translation unit with nested syntax masked as sentinels; adjacent placeholders share one sentinel. Plural branches swap the count for a target-locale sample number (`one`→1, ar `many`→11) and map it back, falling back to a sentinel; categories follow `Intl.PluralRules(target)` (missing ones derived from `other`, unused ones dropped, `other` and `=N` always kept). Escape translated text with `escapeLiteral()` — never concatenate it into ICU unescaped. The result must re-parse with the same argument signature and, when the source is valid rich text, the same tags with tags enabled — or the leaf falls back to source. Fallback routes inside `icu.ts` must rethrow pipeline errors (`pipelineError`), never absorb them. Refuse-by-default also covers compiled FormatJS ASTs (`formatjs-compiled`); i18next catalogs never take the ICU path: a plural/select/selectordinal value there (`containsICUBranching()`) is kept as source and reported as failed with a warning (`FILE_INVALID_FORMAT` under `--strict`, recorded-only in dry runs), since sending it as plain text garbles it. Like every failure fallback, the key is retried (and reported again) by later missing-only runs. `--format raw-json` / `raw-yaml` bypasses detection, so a misdetected ICU catalog takes the ICU path.

## Sync mode

**Default sync mode** is `missing-only`: translate keys that are absent, empty `""`, `null`, or whitespace-only. `--force` re-translates all leaves.

## Changed-source lock

**Changed-source lock:** every non-dry-run writes one lock per target at `<root>/.tl/locks/<target path rel. to root>.lock` (`files/lock.ts`: `{ version: 1, checksums: { <JSON Pointer>: first 16 hex of sha256(source) }, failed?: { <JSON Pointer>: hash of the copied fallback } }`, sorted keys, atomic, written *after* the target). Root: nearest ancestor of the (realpath'd) target containing `.git`, else the target's dir. A target whose directories don't exist yet realpaths its nearest existing ancestor (`realTarget()`), so the lock path is the same before and after `translateFile` creates them. One file per target so a merge conflict / corrupt lock only blocks that target.

**Never put locks beside the target**: Hugo loads every non-dot file under `i18n/` and Vite copies `public/` verbatim. Keys whose recorded hash differs from the current source are re-queued (`PendingTranslation.changed`) only when the existing target value is a string; no lock = trust existing values and just record. Locks are per target, not per source — targets of one source sync at different times. Summary `changed`/`pruned` paths are JSON Pointers; each `failed[]` entry keeps its dotted `path` (kept for --json compatibility, ambiguous for dotted keys) and adds `pointer` (JSON Pointer) and `tag` (the ErrorTag --strict would throw; a failed pipeline call reports its own tag, `TRANSLATION_FAILED` for a non-TlError). Failed keys keep their previous hash so a changed-then-failed key retries, and are listed in `failed`: missing-only runs re-queue them while the target still equals the copied source (a hand-edited value is kept), and a key drops out of `failed` once it is translated or edited (`failed` is omitted when empty, so older readers still parse the lock).

## Abort

**Abort:** `FileTranslateOptions.signal` is checked before each leaf — once aborted the loop stops, unreached keys keep their previous hash and their previous target value; ones the target file lacks stay absent, never `""` (apps render `""` blank instead of falling back) — `TargetCatalog.revertLeaf()` removes them from the data, pruning containers left empty, and YAML writes only what the data holds, so no source text is emitted for them; the target + lock are still written, and the summary has `aborted: true` (dry runs never write; `--strict` throws stay all-or-nothing). The signal is forwarded to `runPipeline`, so the in-flight leaf is cancelled and counts as unreached; a `CANCELLED` pipeline error (`isCancelled()` in `leaf.ts`; `translateLeaf` throws it rather than returning a failed outcome) stops the run the same way, with or without a signal — never let a fallback absorb it as a failed key, or the copied source makes missing-only runs skip the key forever. The CLI passes `session.signal` (Ctrl+C writes the finished leaves, then exits 130/143); corrupt lock → `FILE_PARSE_FAILED`. Use `node:crypto` sha256, not `Bun.hash` (the lock is committed, so the digest must not change across Bun versions or runtimes). `diffForSync`, `pruneTarget` and the lock all read `diffSource` (the source after locale-root re-rooting and plural regeneration), never the raw `sourceData`, or paths stop matching the target.

## Prune

**`--prune`** (`pruneTarget()` in `sync.ts`) deletes target keys/array tail elements absent from the source before write, but never plural forms the target has beyond the source: `stem_<CLDR category>` / `stem_ordinal_<category>` whose stem is in the source, category keys inside a source map whose keys are all categories (Rails nested plurals), and v3 `stem_<n>` / `stem_plural` while the source has `stem` or `stem_plural`. A guard refuses with `PRUNE_REFUSED` when the prune empties the target map (no shared top-level keys, e.g. Rails `en:` vs `ar:` when the root locale is unknown) or removes >50% of target values, unless `allowLargePrune` / `--allow-large-prune`; YAML needs nothing special because its serialize step only appends target-only keys that are still in the data.

## Skip heuristics

**Skip heuristics** (`packages/core/src/files/skip.ts`) pass through URLs, emails, semver, single chars, and ALL-CAPS short tokens unchanged unless `--translate-all`.

## Writing

**Validate-before-rename:** `translateFile` re-parses the tmp file with the format's `read()` before the rename — a malformed serialization can never replace the existing target. `translateFile` translates through a `FileTranslator` port (`session.fileTranslator()` in the frontends, `pipelineTranslator()` in tests and benches), called once per file: it pre-fetches the glossary entries and threads them through `runPipeline` via `glossaryEntries` so the per-leaf hot path doesn't re-query SQLite, and it carries the config's `glossary.maxRetries` and context settings. Error tags live in `packages/shared/src/errors.ts`: `FILE_NOT_FOUND`, `FILE_TOO_LARGE`, `FILE_PARSE_FAILED`, `FILE_WRITE_FAILED`, `FILE_INVALID_FORMAT`, `PLACEHOLDER_MISMATCH`, `PRUNE_REFUSED`, `SAME_LOCALE`.

**Never write over the source:** `sameFile()` compares source and out by realpath (not `resolve()`, which only joins against cwd and leaves symlinked components alone) and refuses with `SAME_LOCALE`, because the language check can't fire when `sourceLang` is `auto`. YAML is fully implemented (`files/yaml.ts`) — comments, scalar styles, and key order round-trip via the `yaml` package's Document API. Update block scalars through `setScalarValue()`, never by assigning `Scalar.value` directly: chomping (`|` vs `|-` vs `|+`) is derived from the value's trailing newlines, and translated text has none.

## Locale-rooted catalogs

**Locale-rooted catalogs** (Rails `en:` root; logic in `files/locale-root.ts`): when the source root has exactly one key equal to the source locale (`sourceLang`, or with `--from auto` the filename's locale token from `files/locale-path.ts`), the source is re-rooted under the target key before `diffForSync`, so leaf paths start with the target key (`fr.…`), and `yamlFormat` renames the pair key in its source document in place. An existing target rooted at the source locale is refused.

## i18next plurals

**i18next plurals** (`files/i18next.ts`): before the sync diff (and after locale-root re-rooting, so hint paths match leaf paths), each plural group is rewritten to the target locale's CLDR categories (`regenerateI18nextPlurals` on the data, `regenerateYamlPlurals` on the YAML source document, called only by `yamlFormat` — both driven by one `planKeys()` so they can't disagree); a source `_zero` is always kept (i18next's count===0 override). Each generated leaf carries a sample count that replaces `{{count}}` (or `{{count, number}}`) in the text sent to the model, then is swapped back; categories holding a single number may drop it. No sample is sent for fraction-only categories, samples ≥ 1e6, or samples that already appear as literals in the text (`hints` value `null` = wanted one but collided); those forms translate plainly and are reported in `summary.pluralFallbacks`. Every target category is still generated (i18next does not fall back from `key_many` to `key_other`). Locale-rule helpers (`pluralCategories`, `pluralSample`, `sampleRegex`) live in `files/plurals.ts` and are format-agnostic — reuse them, don't call `Intl.PluralRules` directly (it silently falls back to the runtime locale for unknown tags).
